# Experience

User journeys. One file per journey — name it for the actor and goal
(`buyer-checks-out.md`).

Each journey covers:

- **Actor and goal** — who, and what they are trying to do
- **Trigger** — what starts the flow
- **Happy path** — numbered steps
- **Edge cases** — failure states, empty states, interruptions
- **Open questions** — `<!-- Q: … -->` for anything unresolved

Describes what the user does — not how the system is built (`docs/system/`) or
what the product is for (`docs/product/`).
